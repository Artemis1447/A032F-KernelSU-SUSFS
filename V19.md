## Reproduce the build

The existing repository and `build-kernel.yml` remain the release recipe. In a clone checked out on `v19-extreme`:

```sh
gh workflow run build-kernel.yml --ref v19-extreme \
  -f config=config/a3core-a032f-v19-extreme.env -f publish_release=false
# Set RUN_ID to the dispatch result. Initial combined run: 45915009611.
gh run watch "$RUN_ID" --exit-status
gh run download "$RUN_ID" -D "artifacts/$RUN_ID"
```

Each build label includes UTC time, run ID and attempt. The workflow uses Clang r383902, the existing 267-symbol PowerVR gate, and `scripts/verify-a3core-v19.py`. V19 additionally requires the SHA-256 of the **whole** Module.symvers from the V17 release (`d035818aâ€¦b45994`), byte-for-byte V17 `.config` except LOCALVERSION, matching embedded IKCONFIG, linked release and compiler, expected final kernel blobs, exact baseline integration hashes and no patch rejects. The known older fuzzy SUSFS port is now a source-controlled, exact-context patch for this pinned kernel. V19 performance patches use `git apply`, which doesn't discard mismatching context to make a patch fit.

Download the raw Image artifact and `pvrsrvkm-ABI-*`. The latter contains the device-scoped **AnyKernel3-V19-*.zip**, integrated `v19-source.tar.gz`, `manifest.json`, `SHA256SUMS.txt`, compiler version, configuration diff, full Module.symvers and GPU CRC report. For offline verification place the raw file named `Image` beside `SHA256SUMS.txt` and run `sha256sum -c SHA256SUMS.txt`. The generic AnyKernel directory artifact is also retained by this workflow. Source archives preserve Linux symlinks; extract on a case-sensitive filesystem. `patches/v19/*.patch` are ordered reversible kernel commits; apply once with `git am` to the stated kernel baseline when working on that delta independently.

## Kernel changes and risk

| Commit | Rationale | What to check on hardware |
|---|---|---|
| `391183c8f99` | Drop unconditional per-buffer ION timing/printk; proven source of work and log traffic on V17. | Per-allocation telemetry disappears; failure paths remain. |
| `480ebf17557` | Use private page heads for temporary SG construction instead of an allocation per chunk. Preserve descending page order, buddy-first ties, pool zeroing/cache semantics and failure cleanup. | Allocation failures under pressure, compositor, camera and GPU buffer import. |
| `701fb8a67d6` | Publish ZRAM write access under the existing slot lock; avoid the success-path re-lock. No change to LZO-RLE or page representation. | Simultaneous writes/idle marking, failed and partial I/O, readback. |
| `0604c5be71d` | Skip a retry wakeup when a rate-limited shared-policy vote is saturated and both requested and actual frequencies already equal the allowed maximum. No V18 stale-vote filtering. | DVFS transitions, responsiveness at scene exit, sustained temperature. |
| `bf4849bc62d` | Leave OF platform-data lifetime to devres on early failed Novatek probe; report allocation failure correctly. | Check the V18 warning, the selected touchpanel and physical input. |

## Manual hardware comparison and rollback

V19 has no runtime result until manually installed. Keep the full current **Boot** backup off-device; on the reference handset the verified V17 backup is `deliverables/V18-stock-derived/boot-v17-device.img`, SHA-256 `cf5d5064730004811dc4ad3a8943a13ae3e40275d55fb33fe70cd344780ced95`. The SM-A032F is single-slot. Validate that your recovery works and that the backup hash matches your own `/dev/block/by-name/boot`; a different ramdisk needs its own backup.

To install manually on the already unlocked reference setup, use TWRP **Install ZIP** on the checked AnyKernel3 ZIP, which replaces the kernel in Boot. The raw `Image` is not an Android boot image. For rollback use TWRP **Install Image â†’ Boot** with the full verified V17 backup (or restore your own TWRP Boot backup). Check the complete Boot SHA-256 in recovery before rebooting. Recovery/DTBO/vbmeta and `/data` do not need replacement. If Android fails to start, enter the separate TWRP recovery via USB and Volume Up + Power at restart.

On each manually selected kernel use at least two fresh boots and the same ROM, enabled modules, USB conditions and launcher state. Before the 240-second mark run `python scripts/bench-a3core.py --serial SERIAL --kernel v19 --at-uptime 240 --out cycle1-240.json`; repeat at 420 seconds, then measure a later settled window separately. The script verifies the kernel identity, takes two warmups and 12 cold launches per window. After these runs, pipe `scripts/profile-a3core-v19.sh`, then `scripts/check-a3core-device.sh`, to `adb -s SERIAL shell -T su -c sh`. They record migrations (including trace-buffer loss indicators), file-backed direct+fsync timings, actual ZRAM readback/footprint for both codecs, frame p95, thermal behavior and service status. Redo the same protocol on V17/V18 for a comparable multi-boot experiment. Do not pool the traced launch with untraced latencies. USB charging current is not a battery-life measurement.
