# Combined V19 EXTREME — SM-A032F only

Device-tested build for LineageOS 21 ARM32 on Samsung's arm64 4.14.199 kernel. The source baseline is `IverCoder/android_kernel_samsung_a3core@81da2968a777556d20847e30b618658905af67a3`. V19 preserves V17's SukiSU-Ultra `4bec532d`, SUSFS v1.5.5 (`77905b5a`, extension ABI 2), PowerVR driver ABI, frequency limits and thermal protection. See the [on-device validation and benchmark results](docs/v19-validation.md).

## Reproduce the build

The [V19 build profile](config/a3core-a032f-v19-extreme.env) is the manual dispatch default on `main`. From a clone:

```sh
gh workflow run build-kernel.yml --ref main \
  -f config=config/a3core-a032f-v19-extreme.env -f publish_release=false
# Set RUN_ID to the dispatch result. Verified combined run: 45915725325.
gh run watch "$RUN_ID" --exit-status
gh run download "$RUN_ID" -D "artifacts/$RUN_ID"
```

Each build label includes UTC time, run ID and attempt. The workflow uses Clang `r383902`, the 267-symbol PowerVR gate, and [`scripts/verify-a3core-v19.py`](scripts/verify-a3core-v19.py). It requires the full V17 `Module.symvers` SHA-256 (`d035818a…b45994`), V17 `.config` apart from `CONFIG_LOCALVERSION`, matching embedded IKCONFIG, the expected kernel release and compiler, the expected source hashes and no patch rejects. The SUSFS port uses an exact-context patch for the pinned kernel. V19 performance patches use strict `git apply`.

Download the raw `Image` artifact and `pvrsrvkm-ABI-*`. The latter contains the device-scoped `AnyKernel3-V19-*.zip`, integrated `v19-source.tar.gz`, build manifest, SHA-256 list, compiler version, config diff, full `Module.symvers` and GPU CRC report. Place `Image` beside `SHA256SUMS.txt` and run `sha256sum -c SHA256SUMS.txt` there. Extract the source archive on a case-sensitive filesystem to preserve its Linux symlinks. The [V19 patch series](patches/v19) contains the ordered kernel changes for use with `git am` on the stated baseline.

The workflow pins Node 24 action versions and retains artifacts for 14 days. The verified build has a permanent download in [GitHub Releases](https://github.com/Artemis1447/A032F-V19-EXTREME/releases/tag/a3core-v19-extreme-20261127), including the CI manifest and checksums.

## Kernel changes and risk

| Commit | Rationale | What to check on hardware |
|---|---|---|
| `391183c8f99` | Drop unconditional per-buffer ION timing/printk; proven source of work and log traffic on V17. | Per-allocation telemetry disappears; failure paths remain. |
| `480ebf17557` | Use private page heads for temporary SG construction instead of an allocation per chunk. Preserve descending page order, buddy-first ties, pool zeroing/cache semantics and failure cleanup. | Allocation failures under pressure, compositor, camera and GPU buffer import. |
| `701fb8a67d6` | Publish ZRAM write access under the existing slot lock; avoid the success-path re-lock. No change to LZO-RLE or page representation. | Simultaneous writes/idle marking, failed and partial I/O, readback. |
| `0604c5be71d` | Skip a retry wakeup when a rate-limited shared-policy vote is saturated and both requested and actual frequencies already equal the allowed maximum. No V18 stale-vote filtering. | DVFS transitions, responsiveness at scene exit, sustained temperature. |
| `bf4849bc62d` | Leave OF platform-data lifetime to devres on early failed Novatek probe; report allocation failure correctly. | Check the V18 warning, the selected touchpanel and physical input. |

## Installation and rollback

For an unlocked SM-A032F on the supported V17 setup, create a full Boot partition backup from your own handset in TWRP, copy it off-device, and verify its complete SHA-256. The repacker below uses that backup as the template so it can preserve your ramdisk, DTB and embedded metadata. It does not generate an OEM signature. The example `Image` hash is for [run 45915725325](https://github.com/Artemis1447/A032F-V19-EXTREME/actions/runs/45915725325).

```sh
python scripts/repack-a3core-v18.py --release v19 \
  --image-sha256 76c4fe051d4c57c6275e82e4bb4840bf4b7a0e6d02a4833ad7f0e8c565a632c7 \
  boot-v17-device.img Image boot-v19-reference-device.img
```

The repacker prints the SHA-256 to expect for your output. The tested 64 MiB reference image had SHA-256 `854b81d58f0c62d4d379716ccecf77959d08bca88c5dce55a9844c0add7a8fb4`. Install the full image to **Boot** in TWRP and verify the complete partition hash before rebooting. This is the installation path tested on the reference handset. The AnyKernel3 ZIP is also available for manual installation and was checked offline.

The SM-A032F is single-slot. Keep your original full **Boot** backup off-device. The tested handset's V17 backup had SHA-256 `cf5d5064730004811dc4ad3a8943a13ae3e40275d55fb33fe70cd344780ced95`; another handset or ramdisk may have a different hash. The [V17 release](https://github.com/Artemis1447/A032F-V19-EXTREME/releases/tag/a3core-v17-sukisu-susfs-20261124) provides the baseline kernel, not a substitute for your full Boot backup.

**Rollback:** enter TWRP and restore your own full V17 Boot backup with **Install Image → Boot**, or use TWRP's **Restore** menu if the backup was created there. Check the full partition SHA-256 before rebooting. If Android does not start, reach the separate recovery via USB and **Volume Up + Power** at restart. Rollback only replaces Boot.

## Reproduce the device measurements

On each manually selected kernel use at least two fresh boots and the same ROM, enabled modules, USB conditions and launcher state. Before the 240-second mark run `python scripts/bench-a3core.py --serial SERIAL --kernel v19 --at-uptime 240 --out cycle1-240.json`; repeat at 420 seconds, then measure a later settled window separately. The script verifies the kernel identity, takes two warmups and 12 cold launches per window. After these runs, pipe `scripts/profile-a3core-v19.sh`, then `scripts/check-a3core-device.sh`, to `adb -s SERIAL shell -T su -c sh`. They record migrations (including trace-buffer loss indicators), file-backed direct+fsync timings, actual ZRAM readback/footprint for both codecs, frame p95, thermal behavior and service status. Redo the same protocol on V17/V18 for a comparable multi-boot experiment. Do not pool the traced launch with untraced latencies. USB charging current is not a battery-life measurement.
